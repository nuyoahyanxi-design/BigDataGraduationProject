## 三、逐段操作与照读讲解词

### 1．0:00—0:30：项目背景

**页面与操作：** 展示标题页或README项目简介，不展开安装说明。预留约5秒用于开场和指示标题。

**讲解词：**

> 各位老师好，我的毕业设计是《基于Spark的学习行为分析与个性化资源推荐系统设计与实现》。项目针对学习记录分散、资源选择缺少依据的问题，将课程学习、行为采集、离线分析和结果展示连接起来。下面我通过学生端和管理员端展示这个流程。

**老师应看到：** 项目目标是可验证的工程闭环，没有预先宣称学习成绩或推荐准确率提升。

### 2．0:30—2:00：学生端与学习行为

**页面与操作：**

1. 在学生首页确认用户名student_demo、角色学习者，不展开恢复码设置。
2. 点击“学习资源”，指示5门正式课程及对应封面。
3. 按上方二选一方式展示PySpark第2章，视频最多播放约10秒，随后暂停。不要点击完成章节或收藏。
4. 在2:00前切到“个性化推荐”。本段预留约30—35秒给点击、加载与片段，播放时暂停朗读。

**讲解词：**

> 这里是学生首页，可以查看账号角色和兴趣标签。进入学习资源后，当前展示五门正式课程，涵盖Spark、Python、数据库和Hadoop基础，每门课程有五个章节。
>
> 学习页面提供视频、教学目标、代码示例和练习。这里以PySpark的筛选与列转换章节为例，展示视频与教学内容如何配合。练习在本地环境完成，平台没有自动评分功能。
>
> 浏览课程、打开章节和播放视频时，系统会记录相应操作。章节需要学生手动确认完成，视频结束不会自动判定完成。课程进度以章节记录为准，全部章节完成才算整门课程完成。开始学习但尚未完成章节时，进度为百分之零是正常状态。

**老师应看到：** 正式课程目录、真实教学内容、章节进度；不把播放操作当作知识掌握证据。

### 3．2:00—4:00：用户画像与推荐

**页面与操作：** 在学生 `/recommendations` 页，先指示画像，再向下展示5张推荐卡。可展开“推荐依据与得分说明”，不要点击“查看资源”。留约20秒给展开、滚动和图表指示。

**讲解词：**

> 这一页把用户画像和推荐结果放在一起，方便解释推荐依据。画像展示兴趣分布、行为次数和学习情况。当前账号的兴趣主要集中在Python和Spark，既参考显式设置，也参考已有学习行为。
>
> 当前批次记录了章节浏览一百零八次、视频播放一百五十六次，以及两个已完成章节。这里的播放次数不等于观看时长。账号开始了五门正式课程，但还没有全部完成其中任何一门，所以课程完成率为百分之零。历史完成操作次数与当前完成课程数分别保留，不混为同一个指标。
>
> 下方推荐先筛选正式课程，再排除当前已完成的课程。内容推荐结合标签相似度、个人行为和资源热度，权重分别为百分之六十、二十五和十五；没有历史行为时采用热度回退。系统还保留热度推荐作为基线。页面得分用于排序，不是推荐准确率或学习效果。
>
> 画像和推荐按离线批次更新，因此刚才的新操作不会在刷新后立刻改变当前结果。这里展示的是已有批次，不是实时训练。

**老师应看到：** 当前完成状态、推荐理由与来源可解释；分数与效果评价明确分开。

### 4．4:00—5:30：管理分析与公开数据

**页面与操作：** 切到admin_demo标签页的 `/dashboard`。指示四个指标卡、学习完成情况及章节统计；有时间时展开数据说明。切换OULAD来源展示概览后，切回平台数据。预留约20秒给切换与指示。

**讲解词：**

> 管理员看板展示平台数据的整体情况。当前正式课程五门，正式课程有效行为九十九次，配套学习者画像四份。两种算法各生成二十条推荐，共四十条。这里的生成条数不是推荐点击量。
>
> 课程目录、学习统计和画像使用同一批次的正式课程范围，排除验收、隐藏和下架资源，历史记录继续保留。章节完成两个，但整门课程完成为零，与学生端一致。
>
> 切换到公开教育数据后，这里展示的是英国开放大学OULAD历史匿名数据，包含两万八千七百八十五名外部学生。它有独立分析流程，不属于本平台用户，也不能用来证明本平台有这么多学生正在使用。两个来源分别展示，避免混淆。

**老师应看到：** 正式统计范围一致、平台与外部数据清楚分离。若公开数据不可用，跳过切换，口述来源边界，不临时运行任务。

### 5．5:30—6:30：技术架构与处理流程

**页面与操作：** 展示 `docs/architecture.md` 中当前架构图，按箭头指示，不现场运行任何任务。预留约10秒切页和指图。

**讲解词：**

> 系统采用Vue前端、FastAPI后端和MySQL数据库。数据库共有十三张表，Spark只读取核心业务和章节相关的八张表的分析字段，不是全库备份。
>
> 数据先进入ODS快照，再经过DWD清洗和统一进度派生，然后在任务内部聚合，生成ADS画像、推荐和看板结果。DWS在这里是逻辑聚合职责，没有独立物理表。结果校验后发布，并保留旧批次以便追溯。
>
> Spark使用本机local模式，没有部署HDFS集群。公开数据使用独立入口和发布目录，不覆盖平台结果。

**老师应看到：** 在线业务与离线计算分工、八表输入、真实分层和本地部署边界。

## 四、现场追问回答（不计入7分钟）

先回答问题本身，老师追问时再补实现细节。以下是可直接说的简短回答；不要把未来方案说成已经实现。

| 常见追问 | 可直接回答 |
|---|---|
| 1．为什么选择Spark？这么少数据有必要吗？ | 当前规模用普通程序也能处理。我选择Spark主要是实现并验证可追溯的离线数据处理链路，并不声称小数据上性能优于其他方案。 |
| 2．Spark运行在哪里？是不是集群？ | 当前在Windows与WSL2本机环境使用Spark 3.5.7 local[2]，没有部署多节点集群或HDFS。 |
| 3．DWS为什么没有独立表？ | 当前聚合职责放在画像、推荐和看板任务内部完成，因此DWS是逻辑层；实际落盘的是ODS、DWD和ADS。 |
| 4．数据库13张表为什么只抽8张？ | 分析只需要核心业务5表和章节3表。画像推荐结果表、AI辅助表及恢复码表不作为这次业务分析输入，更不会导出认证凭据。 |
| 5．141条为什么最后只显示99次？ | 141是课程事件清洗输入，过滤1条后有140条；99是进一步限定正式课程和有效学习者后的统计，两者筛选范围不同。 |
| 6．页面有完成操作，为什么课程完成率是0？ | 历史完成操作是当时发生的事件，当前章节课程必须全部章节完成才算整课完成。历史记录保留，但不补造当前完成数据。 |
| 7．RDD进度0%是不是没有学习？ | 不一定。只要已有章节开始记录，状态就是学习中；百分比按已完成章节计算，未确认完成时仍为0%。 |
| 8．完成率的分母是什么？ | 是已开始的用户与正式课程关系数量，不是平台全部课程数，也不是用户人数。没有开始记录时显示暂无。 |
| 9．播放156次说明看了多久？ | 不能据此推断观看时长。当前记录播放事件与位置，尚未实现有效观看时长统计；播放位置也不是累计时长。 |
| 10．章节操作怎样参与推荐？ | 章节浏览和播放按用户、课程、章节、日期及类型去重，浏览权重0.5、播放1，单课程单日上限3。章节完成不额外重复加分。 |
| 11．使用的是协同过滤或深度学习吗？ | 不是。当前是标签余弦相似度、个人行为和热度的融合评分，加上热度基线，没有实现ALS或深度学习推荐。 |
| 12．60/25/15的权重怎么来的？ | 这是当前实现采用的固定规则参数，不是通过大规模实验训练出的最优权重。其合理性还需要更充分的真实反馈与评价。 |
| 13．推荐100%是不是准确率100%？ | 不是。它是当前算法的推荐得分展示，只用于理解排序，不能解释为准确率或点击概率。 |
| 14．有证明推荐有效的实验吗？ | 项目有独立离线评价入口，但本次展示的结果主要证明功能和发布链路，不据此宣称准确率提升或真实教学收益。 |
| 15．刚才操作为什么推荐没变？ | 页面读取已经发布的离线结果，新行为要进入后续批次才会更新画像和推荐。刷新页面不会触发Spark。 |
| 16．为什么每个人都有五条推荐？ | 当前正式候选只有五门，相关学习者都没有整课完成，所以每种算法当前各有五条。以后完成或下架可能少于五条，系统不伪造补齐。 |
| 17．外部两万多学生是你平台用户吗？ | 不是。它们来自OULAD历史匿名数据，独立展示，不创建平台账号，也不计入平台画像推荐效果。 |
| 18．一千多万条交互是否都是视频播放？ | 不是。它是原数据按学生、资源和相对日聚合的交互行，sum_click是点击汇总，不能映射成单次视频播放或章节完成。 |
| 19．OULAD数据比较旧，能使用吗？ | 数据来自2013—2014年，应如实标注来源和年代。历史数据能否满足任务要求由导师和学校确认，不能为满足近期文献要求改写采集年代。 |
| 20．登录安全具体做了什么？ | 实现了密码哈希、角色权限、一次性验证码和限流，恢复码只存摘要。重置密码会轮换恢复码，并使旧密码对应的令牌失效。当前仍是本地单进程方案，不宣称生产级安全。 |
| 21．没有邮箱怎么找回密码？ | 用户需自行保存恢复码，已有账号可以登录后验证当前密码生成。没有密码也没有恢复码时，当前没有免验证的自助找回路径。 |
| 22．视频完成是否证明学生学会了？ | 不能。章节完成是手动记录的学习状态，平台没有自动评分或知识掌握验证。25个视频的媒体验收也不是学习效果评估。 |
| 23．AI是不是推荐算法？ | 不是。Spark负责画像与推荐；AI是可选的学习答疑增强。课程资料发送受许可和用户确认控制，AI回答需要结合教材核对。 |
| 24．管理员能编辑用户角色吗？ | 当前管理员用户页面是只读查看，不应宣称已实现用户角色编辑或停用。课程与资源维护有独立权限和记录保护。 |
| 25．项目亮点体现在哪里？ | 主要是把学习操作、章节进度、离线分析、可解释推荐和看板串成可追溯闭环，并统一统计范围、保留历史批次；不是发明新的推荐算法。 |
| 26．最主要的不足是什么？ | 平台真实试用规模有限，尚无有效观看时长和充分效果评测，使用单机离线处理，跨机器部署也需要另行恢复环境与数据。 |
