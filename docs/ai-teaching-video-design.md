## 1. 本阶段边界与现状证据

本阶段只审查代码并形成方案，不修改数据库、Spark、推荐、AI助手、学习流程，不生成视频、不调用付费生成服务。

已核对：

- `backend/app/models/courses.py`：course_chapters已有title、position、content、learning_objectives、knowledge_tags、example_code、exercises；已有video_name、video_url、video_cover、video_duration_seconds、video_position。一章一个视频的模型适合第一版。
- `backend/app/schemas/courses.py`：video_url只允许本地/videos/下mp4、webm，另兼容/demo/video.mp4；封面允许/images/路径，拒绝路径穿越。当前不接受任意供应商URL。
- `frontend/src/components/LearningVideo.vue`：已有播放控件、16:9、timeupdate、ended与error处理；已有视频缺失/加载失败提示，尚无独立加载状态机。
- `frontend/src/views/CourseLearningView.vue`：已有播放器入口，play触发video_play，完成章节仍由学生明确确认。
- `backend/app/models/courses.py`、`backend/app/services/courses.py`：chapter_events记录用户、资源、章节、服务端时间、播放位置及幂等信息。播放位置不是观看时长，也不能证明完整观看。
- `frontend/src/views/AdminChapterEditView.vue`：管理员可维护本地视频URL，当前明确无视频上传；这不等同于已有生成任务管理。
- 现有课程维护保留学习开始后的目录冻结、删除保护；视频接入不能绕过这些保护。

结论：无需重建课程学习系统。缺少的是制作过程、文件验收、生成状态和人工发布能力。本次未连接数据库核对实时视频文件，也未执行浏览器或播放测试。

## 2. 本科推荐范围

采用AI辅助教学脚本、配音与课件录屏/合成制作，人工审核后导入本地视频。优先一个代表课程的1–2个章节做真实视频闭环，确认后扩展，不把所有章节一次自动生成作为交付前提。

建议单视频3–6分钟：目标说明、核心概念、可阅读的示例、总结与练习。该时长是制作目标，不是现有限制。代码和技术术语优先使用真实课件/录屏，避免纯生成画面中的文字错误。可先由管理员在外部工具完成制作，平台管理任务记录与发布；不得把手工导入伪称为平台自动生成。

暂缓：数字人、多供应商自动路由、向量检索、完整自动分镜渲染、视频服务器、转码集群、强制看完才完成课程、观看时长用于推荐。

Agnes已具备的问答能力不能视为具备视频或语音生成API。本方案不改动Agnes调用，也不承诺某个供应商支持视频生成；未来如接入真实生成接口，另做官方接口、授权、费用、时长和网络预检。

## 3. 教学脚本与生成流程

脚本来源：当前章节标题、目标、知识点、Markdown正文、代码和练习，课程名称/简介用于定位。采用制作时的内容快照与哈希，不修改章节正文。

步骤：选章节 → 获取资料快照 → 起草讲解脚本与镜头清单 → 管理员核对专业准确性及版权 → 确认外发范围 → 外部制作或未来独立生成适配器 → 导入候选文件 → 文件检查 → 人工预览审核 → 绑定章节 → 学生播放。

脚本建议包含段落编号、讲解文本、画面/代码、预计秒数、资料来源。Spark版本敏感参数注明示例，代码人工校验，不自动执行管理员上传的内容。

不将用户数据、学习行为、密码或Key送入制作服务。课程资料外发需独立授权；课程AI现有白名单不能自动视为视频制作许可。

生成耗时任务不占用同步HTTP连接。V1先用明确的人工状态转换；若后续授权自动生成，采用轻量独立worker读取持久任务，供应商task_id和幂等键用于恢复。超时后先查询任务，不盲目重发付费请求。创建成功只表示任务受理，不能表示视频已生成。

## 4. 文件与URL管理

候选文件放data/media/staging/，正式文件放data/media/videos/，封面放data/media/images/；均为计划目录，本阶段不创建。供应商临时URL不直接绑定章节，审核下载/导入后归本地管理。

视频建议MP4、H.264视频与AAC音频、16:9；这是浏览器兼容制作目标，真实兼容仍需验收。导入时校验扩展名与实际媒体格式、文件大小上限、时长、音视频轨道、可解码性、哈希及路径。建议初始上限200MB，实施时配置化确认。

正式文件名采用资产ID与版本，不用用户上传的原始文件名拼接路径。章节保存稳定相对URL，例如/videos/chapter-58-v1.mp4；封面/images/chapter-58-v1.webp。

开发与交付统一静态映射：Vite开发服务器的/videos和/images映射到本地媒体服务；生产由静态服务器映射同一目录。媒体服务需要支持Range与正确Content-Type。本方案不修改现有播放器URL校验；静态映射具体端口、部署方式属于实施确认项。

更简单的首次演示可手动把审核视频放frontend/public/videos/，但构建会复制大文件，不建议长期管理全部视频。视频、配音和临时产物不提交Git；当前gitignore忽略data，但未全局忽略public下的视频，实施时需补齐媒体忽略规则。

发布时先确保文件可播放，再在一个数据库事务内更新资产发布状态与章节现有视频字段。事务失败旧URL保持；生成失败不清空旧视频。换视频创建新版本，不覆盖旧文件；历史学习记录不删除。当前chapter_events无video_id，旧播放事件无法精确区分视频版本，V1明确接受此限制。

本地静态URL不天然具有登录权限保护。V1仅存可公开的教学材料；若要求保护收费/敏感视频，需独立鉴权媒体方案，不能声称现有JWT保护静态文件。

## 5. 数据库方案比较与推荐

### 方案A：直接扩展course_chapters

已有播放字段足够绑定视频；仅人工制作并粘贴地址可以零迁移。若把脚本、生成状态、供应商任务、失败摘要和版本都加入章节，会把教学资料与制作生命周期混合。

优点：开发量小、现有读取和播放器自然兼容。缺点：多次生成难以审计，重试覆盖信息，候选与正式视频易混淆；异步任务失败可能干扰已发布章节。

### 方案B：新增轻量video_assets表

完整“创建、看状态、更新视频”推荐方案B：只新增一张资产/制作记录表，章节既有播放字段继续作为学生端投影，不新增复杂视频平台表。此处仅为字段建议，不生成SQL或执行迁移。

建议字段：id（主键）、chapter_id（关联章节）、version（正整数）、created_by（管理员）、status、generation_mode（manual_import/provider）、script_snapshot、source_content_hash、provider（可空）、provider_task_id（可空）、request_uuid（唯一）、file_path（内部相对路径，可空）、playback_url（可空）、cover_url（可空）、duration_seconds（可空）、file_sha256（可空）、error_code（可空）、created_at、updated_at、published_at（可空）。不保存Key和原始供应商敏感响应。

约束：章节+版本唯一，request_uuid唯一，章节+状态索引；章节/管理员关联不级联删除历史资产。发布时锁定章节保证只有当前URL投影生效。同一章节只有一个活动制作任务，重试复用任务身份，更新发布另建版本。

状态：draft → generating（仅自动制作）/awaiting_import（人工制作） → ready_review → published；失败为failed，废弃候选为cancelled。旧published被新版本替换后为archived；供应商成功不自动published。重新制作失败旧published保留。

优点：状态可追溯、候选与正式隔离、可恢复及版本管理。缺点：新增迁移和管理员服务，需要维护章节视频投影一致性。

最终建议：先确认方案B的一表最小设计；实施优先人工制作/导入闭环，自动供应商适配放后续独立阶段。如时间非常有限，退化为A的零迁移URL绑定版本，明确不提供平台生成状态管理。

## 6. 管理员页面流程

复用/admin/courses/:id/chapters与章节编辑入口，增加“教学视频”管理入口，不把复杂制作表单堆到课程列表。

选章节 → 查看当前视频/版本 → 创建制作草稿 → 编辑并确认脚本 → 选择人工导入或未来生成 → 查看任务状态/失败原因 → 预览候选 → 人工审核发布 → 返回章节。

只管理员可创建、查看制作详情、上传、重试和发布；学生只能读已发布章节视频。状态显示含更新时间，失败说明区分网络、生成、文件校验和审核拒绝。禁止显示凭据。更新视频保留当前版本直至新版本发布成功；刷新页面能恢复任务状态。

计划接口仅为设计：创建章节视频制作记录、查询记录/版本、更新草稿、导入候选、发布候选。权限复用require_admin；具体路径在实施设计确认，不替换既有章节接口。

## 7. 学生页面流程

保持当前学习页布局与AI面板。课程 → 章节 → 加载视频 → 播放/暂停 → 阅读资料和练习 → 手动完成章节。

播放器显示idle/loading/ready/playing/ended/error。无视频：显示“本章节暂未提供教学视频，可先阅读课程资料”；加载中显示轻量提示；失败显示重试提示，不冒充教学文件生成中。视频失败不阻塞正文、练习或章节完成。

沿用video_play事件及event_uuid幂等、用户隔离、章节归属校验。timeupdate仅本地显示，不逐秒写库；ended目前只改变前端提示，不新增完成事件。本阶段及V1不把播放结束等同于章节完成，不声称精确观看时长、强防作弊或跨设备续播。

未来观看统计需独立设计停留区间、拖动、暂停、后台标签页、视频版本和去重；不复用播放位置当累计时长，不在此次改变Spark或推荐输入。

## 8. 数据流程与模块边界

教学资料只读 → 脚本快照 → 制作任务/候选视频 → 人工审核 → 本地正式文件 + video_assets发布记录 → course_chapters既有视频字段 → 既有课程查询 → HTML5播放器 → 既有chapter_events。

既有章节完成 → 原有课程完成事件 → 原有learning_events → 既有Spark ODS/DWD、画像、推荐、Dashboard。制作任务不进入学习行为表；不宣称Spark已分析视频观看时长。

AI问答助手与视频制作是并列增强能力，复用登录和管理员角色，不复用或修改课程问答检索、references与Agnes调用链。

## 9. 分阶段开发与验收

1. 方案确认：确认A/B、制作方式、公开媒体范围、预算及真实视频数量。本阶段结束等待确认。
2. 素材验证：选1章人工产出视频，验证专业内容、音频、字幕/术语和浏览器播放；记录真实制作工具与来源，不改业务。
3. 视频资产基础：确认一表字段后单独迁移，实现管理员草稿、导入、预览、人工发布；保持旧25章节及学习记录。
4. 静态交付与学生提示：完成路径映射、Range测试、加载/失败状态；沿用章节事件和完成逻辑。
5. 可选自动制作：只有独立供应商接口预检通过且授权后实施worker、任务恢复、成本限制；不作为毕设必达条件。
6. 回归与答辩：后端、前端、类型检查、生产构建，真实管理员发布→学生播放→章节学习→原Spark链路回归；生成各阶段报告并逐阶段确认。

必要测试：管理员权限、学生拒绝制作、文件伪装/路径穿越、重复创建、失败旧视频保留、发布事务回滚、版本替换、Range请求、无视频/加载失败、play事件幂等、视频结束不自动完成章节、原AI/推荐/Spark不受影响。

## 10. 风险与待确认项

专业准确性、知识与配音版权、外发授权、制作成本和网络稳定性优先于画面效果；人工审核不可省略。公开静态媒体限制必须说明。离线人工导入作为生成不可用时的稳定备选。

待确认：实际制作工具/供应商、授权预算、是否需要平台自动生成、目标章节、最终媒体存储位置、公开访问范围及video_assets字段。所有字段、页面状态、接口和测试均为设计，未声称已实现。
