# AI课程视频自动导入设计

2026-10-10。用户授权本阶段资源管理实现，不生成视频、不写正式数据库、不提交Git、不运行Spark或切换发布指针。

现状：resources → course_chapters.video_url → 课程GET响应 → LearningVideo。正式25章仍保存/demo/video.mp4；现有字段足够支持，无需数据库迁移。

选择方案A的只读呈现映射：默认frontend/public/videos/course_<resource_id>/chapter_<chapter_id至少3位>.mp4。学生课程读取时若标准文件通过大小及MP4容器/视频轨检查，在响应副本中替换video_url，时长交由真实metadata读取；否则保留原URL。管理员编辑读取仍返回数据库原值，避免保存无关内容时将呈现映射意外写库。新课程只要有合法章节，即按同一规则工作；不维护25章硬编码映射文件。

播放事件仍接受video_play；未来原video_url为空而标准文件有效时允许原播放事件，不增加事件类型或改变完成逻辑。UUID桥接、章节进度与整课完成算法保持原样。

新增只读扫描工具：读取MySQL课程/章节目录（可用离线catalog做测试），扫描标准路径，检查缺失、大小、容器、视频轨、课程存在、章节归属、目录命名和目录外链接；输出JSON/Markdown，退出码区分完整、缺失或异常。使用与运行时相同检测函数，不把.mp4后缀或HTTP200等同于解码播放通过。无ffprobe时明确结构检查等级，真实播放另行验收。

使用临时HTTP/MP4结构字节夹具测试自动规则，不生成可播放视频，不放正式目录。用户若提供既有合法视频，可在隔离目录进行真实解码验收；没有文件时保留该门禁，不伪造通过。保护证据：正式章节媒体字段/进度/事件摘要、schema和latest哈希在本轮前后对照。所有改动可按本阶段文件备份回滚，不覆盖此前未提交工作。
