# 前后端用户认证设计

日期：2026-10-05。仅登录、用户状态、JWT 请求及路由保护。本次用户已授权设计和实现，不进入资源等模块。

## 接口与数据模型

POST /api/auth/login 使用 JSON username、password；响应 access_token、token_type、expires_in。随后 GET /api/users/me 获取 id、username、nickname、role、status、interest_tags、created_at、updated_at。前端只声明对应类型，不改变后端模型或数据库。

## 架构与状态方案

登录页负责输入校验、提交锁、公共错误提示，密码不裁剪、不持久化，离开页面自然释放。Pinia auth store 保存 token、当前用户和过期时间，role 从当前用户派生。API 层只有登录与当前用户函数。Axios 通过注入回调获取 Token，避免 http 模块与 store/router 循环依赖。

sessionStorage 仅保存 Token 和过期时间，不保存密码或用户信息；同标签页刷新恢复，关闭标签页结束会话。保存失败时保留内存会话并提示刷新无法恢复。状态恢复会调用 /users/me 验证 Token，不能仅相信缓存或客户端 JWT 声明。网络错误保留 Token，显示重试入口；身份失败清除缓存。该方案适合本机毕设，仍存在 XSS 读取 Token 的风险，公网部署可单独设计 HttpOnly Cookie，当前不扩大后端范围。

## 认证与路由

首页 requiresAuth，未登录跳到 /login。登录成功获取当前用户后跳首页。刷新受保护页面先恢复会话，再放行。Axios 自动加 Bearer；登录请求跳过认证头。401 仅使使用当前 Token 的请求失效，避免旧请求撤销新会话；登录错误密码不触发全局退出。定时检查 expires_in 对应的本地截止时间，后端仍为最终认证依据。不实现刷新 Token、跨标签页同步或后台角色页面。

## 阶段限制

无注册页面、兴趣编辑、资源、推荐、数据看板、管理后台。首页仅展示当前用户资料和退出按钮。不记录密码或 Token 到日志、脚本常量、报告、截图。测试失败不输出原始认证响应。
