> 正文初稿，基于v1.0-defense-ready（9dbbb9d911b194108f4e404457677ba013f196fb），编制日期2026-10-11。本章描述已实现系统对应的需求及约束，不把需求目标写成已经完成的性能或用户效果实验。

## 3.1 需求分析范围

大数据智能学习平台的需求不仅包括课程页面和用户操作，还包括行为记录进入分析过程后如何形成可解释的展示结果。因此，需求分析需要同时关注在线业务和离线分析。在线部分负责身份认证、资源访问、章节学习及状态维护；离线部分负责固定输入、清洗有效行为、生成画像与推荐，并提供可以追溯的结果来源。

系统采用学习者和管理员两类角色。Spark任务不作为第三类可登录用户，而是由授权操作者在独立运行环境中执行的批处理程序。课程AI助手是学习业务的扩展功能，其外部模型调用不能代替学习行为采集，也不能自动改变进度或推荐评分。上述角色与职责共同限定了本章讨论范围。

本项目面向本科毕业设计的可运行工程闭环。需求中的正确性、可解释性和可追溯性可以通过源码、规则测试与既有产物核验；吞吐能力、真实学习效果和生产可用性需要额外验证。本章不设置没有实际测量依据的并发数、响应时间或效果提升目标。

## 3.2 用户需求

### 3.2.1 学习者需求

学习者首先需要通过登录识别自身身份，在首页查看角色与兴趣信息，再通过资源列表寻找课程。资源搜索和筛选应围绕系统已有分类与内容提供入口，课程学习页应展示明确的章节目录、教学目标、知识正文、示例代码、练习与视频，避免仅提供无法解释学习内容的单一链接。

学习过程中，用户需要知道哪些章节已完成以及课程当前状态。系统应区分浏览、播放与手动确认完成，不把视频结束自动等同于学习完成，也不把完成率解释为知识掌握率。练习要求属于自主学习指导，当前系统不自动执行用户代码或评分。

学习者还需要查看自己画像与推荐的来源。推荐页应展示兴趣和行为摘要、推荐理由、得分以及结果生成和统计截止信息，使用户理解推荐并非在每次点击后实时训练。推荐界面需要过滤当前不可见或已完成资源，防止将明显不适合继续学习的候选直接展示。

对于课程AI扩展，学习者需要明确所使用的课程资料与引用。系统应要求外发确认、检查资源许可和额度，并把问答历史与学习进度分开。AI输出属于辅助解释，不能替代能力评价或将回答成功视为章节完成。

### 3.2.2 管理员需求

本文中的管理员需求限定为只读查看用户摘要、资源与课程信息、章节结构、发布批次和分析看板。用户列表不提供管理员修改他人账号、角色或状态的功能；管理页面的读取仍须由后端检查权限，不能仅依赖前端按钮是否可见。

管理员需要查看用户摘要、发布批次及数据分析看板。看板应说明用户行为趋势、学习完成情况、资源分类和推荐发布结果的统计含义，并保留来源与截止时间。部分资源信息读取当前MySQL，部分行为指标来自冻结批次，这种差异应明确标注而非隐藏。

冻结源码另保留资源、课程和章节维护接口，这些接口不纳入本文管理员只读展示的验收范围。章节结构在已有学习记录后受业务约束，代码中存在写接口不表示其已完成最终版真实浏览器验收，更不能推导出用户管理CRUD能力。

### 3.2.3 分析执行与维护需求

授权运行人员需要通过独立命令执行Spark处理任务，确认输入批次、质量检查、结果状态与发布指针。任务失败时应保留检查信息及历史版本，不把失败产物视为最新有效结果。运行人员不是页面中的新增角色，也不存在由本项目实现的集群调度平台。

维护人员还需要能够根据固定依赖、数据库迁移和运行文档准备环境。源码克隆不能自动恢复数据库、凭据和被忽略的分析数据，因此部署资料需要说明这些边界。秘密信息应由既有安全机制加载，不能写入公开报告或截图。

## 3.3 功能需求

### 3.3.1 用户认证与权限

系统应支持注册、登录及当前用户信息读取，并对兴趣信息按接口规则处理。认证令牌应具有有效期，后端应校验用户及角色状态。学习者读取本人进度、事件、收藏、画像和推荐，管理员才能使用相应管理接口；客户端不能通过任意用户编号直接读取其他学习者私有记录。

前端需在会话过期或失效时给出一致处理，页面跳转不能绕过后端检查。需求仅涉及当前两类角色，不扩展成多租户、复杂组织权限或未经实现的细粒度RBAC平台。

### 3.3.2 资源与章节学习

资源列表需要支持标题搜索和分类筛选，并区分已发布与不可见资源。课程详情和学习页根据资源及章节关系展示内容，章节应按位置排列，视频标题和实际教学内容应对应。正式视频目录采用已有课程及章节命名规则，不能为了页面显示重新绑定章节。

学习流程需记录章节访问、视频播放与确认完成等已支持动作。章节身份与所属课程必须匹配，部分动作要求先打开章节；没有视频的章节不能被当作存在播放资源。进度计算依据已完成章节数与章节总数，整课完成按既有规则产生课程级状态变化。

系统提供五门课程的二十五个正式MP4，这是视频交付范围，不表示数据库只能存在二十五条章节记录。数据库其他章节与视频目标集合应分别统计。

### 3.3.3 学习行为记录

主行为包括资源浏览、学习开始、学习完成、收藏添加和取消收藏。后端需保存身份、资源、事件类型、时间、来源、有效性及请求语义信息，采用UUID和约束识别重复或冲突请求。当前状态变化与事件记录应保持一致，不将无变化回执无限累积为有效学习行为。

章节操作保存在独立章节事件体系中。课程首次开始和整门课程完成通过后端桥接生成主学习事件，供五表分析输入使用；章节访问和视频播放并不全部直接输入Spark。播放位置不是观看时长证明，不应将其转换成未经实现的完整观看认证。

### 3.3.4 分层数据处理

Spark需要按固定输入范围读取五张核心表的分析投影，生成ODS快照，再按照规则形成DWD有效行为与质量信息。分析投影应排除账号密码哈希和其他非必要内容，不把ODS当作完整备份。

任务内完成聚合后生成ADS画像、推荐和日指标。DWS为任务内逻辑聚合职责，不存在独立物理落盘层、独立物理表或落盘目录。批次输出需要记录来源、截止、状态和文件检查信息，成功产物与失败产物必须区分。

### 3.3.5 用户画像与推荐

画像应覆盖快照中有效学习者，区分显式兴趣、行为兴趣和缺少证据的情形，提供活动及学习偏好统计。页面应展示统计截止与批次，不对学习能力作出推断。

推荐采用已实现的popular_v1和content_v1。前者提供行为热度基线，后者结合标签匹配、归一化个人行为与资源热度，并按无历史行为分支回退。候选应遵守用户、资源状态与完成过滤规则，输出理由和稳定排名。线上默认Top-N与独立实验Top-10是不同使用场景，不能混称为页面固定展示十条。

### 3.3.6 管理看板与AI扩展

看板应显示统计来源、样本性质、清洗情况、用户活动、资源分类、完成情况与推荐结果信息。对冻结批次和当前资源统计采用不同来源说明，刷新只读取既有结果，不触发Spark。

课程AI应在确认和许可后检索相关资料，调用外部模型并提供引用与个人历史。当前实现使用关键词检索，没有向量数据库、多轮语义记忆或自训练推荐模型。外部调用失败不应被解释为学习分析链路必然失效。

## 3.4 非功能需求

### 3.4.1 数据一致性与正确性

正确性首先体现在身份、资源状态、请求语义、进度与事件之间的关系。在线通过事务、锁与约束控制状态变化，离线通过快照截止、有效性规则、清洗报告和结果读回检查减少来源不一致。指标正确性需在具体统计定义范围内讨论，不能以“数据正确”推导真实学习行为完全准确。

### 3.4.2 安全与隐私

系统应采用密码哈希和JWT认证，后端校验角色与资源访问条件。密钥不进入Git、文档、截图或浏览器构建变量；分析投影排除密码哈希。AI资料外发需独立许可与确认。这些是实际实现的安全控制，不代表经过全面渗透测试或具备生产安全认证。

### 3.4.3 可追溯与可解释

处理结果应保留源批次、统计截止和生成时间，使画像、推荐与看板能够核对来源。推荐应提供理由，页面得分不被命名为准确率；完成率说明其分母与进度含义。历史产物与失败报告应留存，但不能被当作当前版本证据。

### 3.4.4 资源限制与稳定性

当前Spark运行在local[2]，配置driver内存、Shuffle分区、表抽取上限、候选对数和输出行数。超限按任务规则拒绝，而不是截断后伪装成功。以上参数是本机保护和处理边界，并非已验证的最大吞吐量。

接口与页面需要对未登录、无结果、数据不可用和外部模型失败提供明确状态。系统没有实现高可用集群、自动扩缩容或完整生产监控，不能把本机启动成功写成持续生产稳定性结论。

### 3.4.5 可维护与部署可复现

前端、后端、Spark计算、迁移与文档分目录管理，使用依赖清单和锁文件恢复软件版本。测试与真实页面证据用于支持不同层次的核验。新机器还需恢复数据库与本地凭据等运行条件，当前没有全新机器一键恢复验收，因此可复现性应表述为具有恢复依据而非无条件直接运行。

## 3.5 用例分析

### 3.5.1 用例关系

学习者用例包括登录、浏览资源、章节学习、确认完成、收藏、查看画像推荐与使用AI助手。管理员用例包括登录、只读查看用户和课程信息、查看发布批次及数据看板。离线执行流程使用读取快照、分析、校验及发布任务，不属于学习者页面触发的普通用例。

登录是受保护访问的前置条件，但仅登录并不授予管理权限。章节完成需要满足既有章节操作规则；AI课程问答还要求许可、外发确认和额度。画像推荐的前置条件是存在可用发布结果，没有结果时应提供明确空状态。

### 3.5.2 UC-01：登录与身份确认

| 项目 | 内容 |
|---|---|
| 参与者 | 学习者或管理员 |
| 前置条件 | 已有有效账号及本人保管的密码 |
| 基本流程 | 输入凭据→后端校验→获得令牌→读取当前用户→进入相应页面 |
| 异常流程 | 凭据无效或账号非active时拒绝；令牌过期后要求重新登录 |
| 后置条件 | 浏览器获得受限会话，后端后续请求仍执行权限检查 |

### 3.5.3 UC-02：课程学习与行为记录

| 项目 | 内容 |
|---|---|
| 参与者 | 学习者 |
| 前置条件 | 登录；课程及章节可见且关系正确 |
| 基本流程 | 进入课程→访问章节→展示内容和视频→按规则记录事件→需要时手动完成 |
| 异常流程 | 资源不可用或章节不匹配拒绝；未打开章节的部分动作拒绝；重复UUID校验语义 |
| 后置条件 | 相应章节记录与进度保持一致；首次开始/整课完成时桥接主事件 |

视频播放不是本用例完成的能力证明。完全只读展示应使用已有截图和记录，因为正常访问课程可能产生事件。

### 3.5.4 UC-03：查看画像与推荐

| 项目 | 内容 |
|---|---|
| 参与者 | 学习者 |
| 前置条件 | 登录；存在相应可用发布信息，或允许返回无批次空状态 |
| 基本流程 | 打开推荐页→读取发布指针及配套画像→过滤当前不可见/已完成候选→展示理由和来源 |
| 异常流程 | 无批次返回明确状态；发布信息损坏或配套结果异常不能冒充成功 |
| 后置条件 | 用户了解已有批次结果；不触发Spark重新训练或发布 |

### 3.5.5 UC-04：管理员查看数据看板

| 项目 | 内容 |
|---|---|
| 参与者 | 管理员 |
| 前置条件 | 有效admin会话；配套统计产物可读取 |
| 基本流程 | 打开看板→查看来源与截止→查看行为、完成、分类及推荐统计 |
| 异常流程 | 学习者无管理权限；产物不可用时显示对应状态 |
| 后置条件 | 只读获得系统统计；刷新不运行Spark |

### 3.5.6 UC-05：课程AI问答

| 项目 | 内容 |
|---|---|
| 参与者 | 学习者 |
| 前置条件 | 登录、可见课程、资料许可、外发确认及可用额度/模型 |
| 基本流程 | 提问→检查规则→关键词检索课程资料→调用外部模型→返回回答及引用→保存本人历史 |
| 异常流程 | 未许可、未确认、超额度、超时或供应商失败时按原规则处理 |
| 后置条件 | 形成问答及引用记录，不自动完成章节或更新推荐 |

## 3.7 本章小结

本章从用户和计算职责出发，归纳了认证、课程、事件、分析、画像推荐、看板与AI需求，并通过用例说明前置条件和异常边界。需求分析将学习进度与能力、业务事件与分析输入、当前数据与离线批次分别处理，为下一章总体和数据设计提供依据。

## 答辩可能问题

1. **需求是否来自真实用户调研？** 本章按毕业设计场景与现有实现整理，不声称进行了未记录的问卷或访谈。
2. **为什么把分析和在线业务分开？** 请求处理与固定快照计算职责不同，便于解释结果来源。
3. **学习者能查看别人画像吗？** 私有请求由服务端身份与权限约束，不由页面任意选用户。
4. **播放位置是否学习时长？** 不是，仅记录部分播放事件信息，无强制观看证明。
5. **页面是否能启动Spark？** 不会，页面读取发布结果，任务独立运行。
6. **DWS对应哪些表？** 没有独立表，仅任务内聚合逻辑。
7. **如何规定性能需求？** 说明实际保护参数和运行条件，不填入未测的并发或响应承诺。
8. **AI会自动改变进度吗？** 不会，问答与学习事件、推荐计算分开。
9. **如何保证只读演示？** 用已有截图和记录替代会产生事件的学习操作。
10. **需求覆盖是否等于全部验收通过？** 不是，源码、测试、页面与用户效果属于不同证据层次。
